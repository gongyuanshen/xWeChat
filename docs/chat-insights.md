# 聊天画像与消息标签

在聊天工具栏点击「聊天画像」，右侧聊天区域切换为画像仪表盘，左侧会话列表保留。「返回聊天」恢复聊天及未发送草稿、附件；点击原文出处也会回到聊天定位。在顶部「分析对象与启动」选择群整体或具体成员，再点击开始；提交和运行期间不能切换成员，取消后可以更换。分析设置、时间范围、模型管理、历史和已存标签开关集中在「分析设置与历史」中。默认使用「本地 Laya · 统计画像」，API 模式必须手动选择。默认范围为最近七天，结束时间不包含在范围内。打开画像、查看历史及显示已存标签不启动模型；消息自动识别由输入区「图片／文件」旁的「意图识别」开关控制，与画像共用分析方式。

仪表盘显示真实覆盖量、人物信息、亲近倾向、MBTI 四轴、互动雷达、常见话题和摘要，依据与不确定性继续保留。群整体采用同样的卡片布局，人物 MBTI 区换成群聊氛围；「发言人数」仅指选定范围实际发言者，不是群总人数。亲近倾向显示已有分数，不额外推断关系等级；未知分数不会补成零。

本地模式第一次使用需点击「下载模型」，或展开「导入已有模型目录」选择完整目录。下载显示进度，可暂停并显式继续；模型共 681,238,131 字节（约 681 MB），安装包不包含权重。每个文件按固定版本检查大小与 SHA-256，全部通过后才显示就绪。下载失败不会自动改源、自动重试或调用 API。导入会校验并复制到应用模型目录，不修改原目录。

Laya 是分类与评分模型：消息标签使用细分类候选，画像继续使用大类情绪、意图、六维统计、关系信号、常见用词及简短统计摘要，不自由生成长篇解释。它显式使用 CPU（4 线程），模型就绪后的推理不联网，也不要求 API Key。需要详细文字分析时选择 API 模式。两个来源的历史和消息标签分开显示，已有 API 历史继续保留。

单聊提供人物摘要、话题、交流特点、六维互动雷达、情绪、互动亲近倾向和 MBTI 聊天推测。群聊可分析群整体，或按需加载已经发言的成员并选择其中一人。群整体没有好感度或 MBTI，群成员没有单聊好感度。成员以微信 ID 区分，显示名相同不会合并。

新建私聊画像任务在消息读取入口按对方的微信 ID 筛选，本地和 API 只保存、统计和分析对方的消息，本人消息不进入本任务。选择群成员时同样仅处理该成员；群整体仍处理全部成员。相邻上下文也只使用分析对象前面最多三条有效文本。读取消息数包含该对象的图片等非文本，分析进度只计算有效文本。任务保存 `read_scope` 和 `analysis_scope`（私聊为 `peer`、群成员为 `member`、群整体为 `conversation`），界面分别按读取范围和分析范围解释计数。旧私聊任务曾分析双方文本；旧成员任务缺少 `read_scope` 时覆盖量仍表示全会话读取，更早未保存 `analysis_scope` 的成员任务还曾分析全会话文本。历史结果与计数保留并提示原范围，需要按新范围处理时点击「重新分析（新任务）」。

聊天窗口的自动意图识别只将私聊对方、群聊其他成员的已加载文本加入队列，初次打开、翻历史、新消息及相邻前文均排除本人消息。后端从真实消息源核对发送归属；批次或前文包含本人消息时明确失败，不调用模型。所有本人气泡的历史标签不再恢复或显示（包括旧手动画像标签），原存储记录保留；其他人的已有标签继续复用，不因升级重复识别。群聊顶部氛围先排除本人，再统计最近20条其他成员已识别消息；快照使用账号元数据中的本人身份，实时账号复用原生微信 ID，避免与带后缀的目录名混淆。消息自身携带的引用文字仍仅作语境，不生成被引用者的标签。

MBTI 只有已经分析到至少 100 条目标本人有效文本后才开放；每个维度仍可为「证据不足」。100 条只是展示门槛，不代表结果可靠或具有心理测量效度。所有分数都是对所选文本的模型估计，不是概率、真实心意或心理诊断。

画像历史支持单条移除或按当前账号、聊天、群成员与分析方式清空。清理只设置 `history_hidden`，保留任务、画像、消息标签和原文依据，也保留自动识别使用的已存画像及缓存。排队或运行中的任务不能单条清理，批量清理会跳过它们。清理不改变结果时间顺序；重新打开时仍可恢复当前对象和模型的最近结果，也可查看已保留的结果。

手动画像新任务默认复用符合当前设置的已保存标签，失败或取消任务中的有效部分也能复用；无需重复识别已完成的消息。「从头重算全部消息」仅对本次请求关闭复用，不修改旧任务。进度区分复用与新识别数量；扫描仍读取当前选定范围，已复用消息也进入相邻上下文及最终画像。API 最终画像仍会按完整材料重新整理，不能把省去标签识别等同于整项任务零调用。

复用只在手动任务之间进行，核对账号、会话、分析对象、读取范围、数据源、模型配置和版本，以及消息身份、时间、发送者、原文和引用内容。标签引用的原文也必须存在于当前材料且未变化；运行中任务不会被当作复用来源，隐藏历史入口仍保留可用结果。本地 Laya 还要求对应统计结果与分类规则可用。新任务记录标签来源任务，原费用记录不复制为新调用。复用是在沿用当时的历史判断，并不等同于结合新语境重新推理；需要重新判断已有标签时使用从头重算。

## 消息标签样式与当前功能范围

消息标签采用原项目的紧凑文字行，例如「情绪 开心　意图 分享」：字段名浅色、结果正常文字色，无底色徽章、冒号或单独的「依据」按钮。Laya 与 API 使用同一组件。鼠标悬停或点击标签行可查看原始分析依据，键盘可聚焦并展开。

| 原项目介绍的能力 | 当前项目状态 |
| --- | --- |
| 每条消息显示一个情绪、一个意图，关闭后恢复已有标签 | 已支持；自动开关和缓存按账号、会话、模型来源保存，手动标签显示仍独立控制 |
| 本地细分类，例如期待、试探、婉拒 | 已接入动态候选分类；词句仅检索候选，最终标签来自模型，低置信度保留未知 |
| 每个标签四字以内 | 本地候选和 API schema 均严格限制最多四字，超长结果报错 |
| 结合近期聊天和已保存画像识别消息 | 近期聊天、引用和同账号、会话、模型来源的发送者画像参与判断；画像仅弱参考，不能替代当前原文 |
| 打开会话、翻历史、新消息到来时自动分析 | 开启意图识别后，已加载消息按批串行处理，新消息和翻历史追加排队；默认关闭 |
| 分析过程中逐步显示结果 | Laya 每条完成后保存；API 流中每个完整标签通过校验后立即保存，关闭、缺项或断流不抹除先前结果 |
| 纯标点参与分析 | 非空标点文本可参与，结果仍取决于模型 |
| 聊天顶部人物情绪、群聊氛围 | 单聊展示最近已分析对方消息的情绪；群聊展示最近20条其他成员已分析消息的统计氛围，排除本人 |

同一个 Laya 权重可以供不同分类流程使用；采用该模型不等于自动具备调度和展示功能。手动消息标签与统计画像分别保存细分类原始输出和粗分类原始输出，便于追踪各自依据。

## 自动意图识别

聊天页开启「意图识别」后，使用当前所选的 API 或 Laya 方式分析已加载文本。API 模式会发送这些原文并可能产生调用费用；Laya 需先准备完整模型。关闭开关会停止本范围的活动批次并隐藏自动标签，保存的标签在重新开启后恢复。已开启的范围在再次进入时延续这一选择，失败或应用退出中断的批次必须点击重试，不自行重新计费。

每批最多20条目标消息，附最多3条相邻前文；同时到来的历史和新消息在当前批次结束后继续排队。缓存按照账号、会话、模型来源、消息身份和原文指纹匹配，命中不重新调用。切换会话后已提交的旧批次在原范围完成，不向新会话继续提交旧消息。自动批次独立存储，不把每次翻页都塞入手动「分析历史」。

消息顶部状态仅反映已分析材料。单聊取最新对方消息，群聊先排除本人消息再取最近20条其他成员消息，不随画像面板的成员筛选改变。群统计仅在某一情绪占样本至少一半且唯一领先时展示，否则明确为不明确；未知消息仍计入样本数。翻历史不会用较早情绪覆盖较新状态。此统计不是全体群成员的心理结论。

已保存画像只取同账号、会话、模型来源且匹配发送者的最近人物摘要、交流特点和不确定性；群整体画像不冒充成员画像。旧画像是弱参考，当前原文优先。API 和 Laya 均保留完整选定参考字段，不通过截断或偷偷去掉画像绕过容量限制。

## 原文与范围

仅分析非空文本，以及引用回复中发送者自己写的文字；被引用的话独立作为上下文，不计为本人的表达。图片、音视频、文件等只记录跳过数量。任务保存准确范围、模型、数据来源、覆盖量与结论出处，点击出处可以定位原消息。消息内容更改后不再显示其旧标签。

实时账号必须能连接实时消息源，否则任务失败；导入账号明确使用导入快照。不能把旧快照当作当前聊天悄悄继续。大范围聊天先分页保存本次材料。API 模式按模型输入/输出容量分批生成标签，画像材料累计到预算阈值前先生成有出处的压缩画像，再继续读取材料，最后整理最终画像。前一窗口相邻消息参与语境理解；较早画像只携带已生成结论和出处身份目录，完整原文保留在本地供复查，不会每轮重复发送全部历史。

本地模式每完成一条消息分类便保存细标签并更新已分析目标文本的累计统计画像，失败前完成的画像仍可查看。最多使用三条相邻消息及引用文字作为语境；细标签同时读取身份和模型来源匹配的已保存画像。画像作为完整弱参考传入，不能覆盖当前发言，也不作为新增事实的证据。Laya 的固定输入上限为 1024 token（包括问题、选项、文本、上下文和画像）；超过限制时明确报错，不截断文本或悄悄省略画像。API 的 258k 预算和压缩策略不适用于 Laya。

## 模型与错误

2026-10-03 修复官方 MiMo `mimo-v2.6-flash` 缺失 JSON 输出能力声明的问题。该型号的自动元数据现在依据[官方结构化输出文档](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/text-generation/structured-output)登记 `structured_output=true`，严格标签与画像请求因此显式使用 `response_format={"type":"json_object"}`。能力仅适用于精确型号及官方 HTTPS 接口，不按前缀推断代理能力，也不覆盖用户或上游明确配置。未放宽标签长度、来源或证据校验；没有裁剪返回内容、自动重试或降级。

标签调用审计现在记录实际输出格式、预期标签数，以及 JSON 开头／尾部的失败类别；字段错误只保存白名单路径与类型，不保存原始模型文本或未知字段名。2026-10-03 用用户已授权群聊中失败任务的第 61～80 条及原三条前文，在隔离存储中复测当前 MiMo API：单次请求 20/20 标签通过，正常 `stop`，输入 2811 token 与原失败调用一致。该验证不代表整段 665 条已重跑完成；原始失败任务和已完成标签保留。见[批次验收记录](../tmp/api-label-failure/real-batch/report.json)。

随后 180/672 条处的失败来自另一条路径：原调用已经使用 JSON 模式，前九批成功；第十批在检查服务终止状态时，被统一报成 `output_invalid`。旧审计未保存该状态，因此不能断言历史请求具体是内容过滤、工具调用还是服务异常。同一批第 181～200 条及三条前文的实际 API 复测得到 20/20、正常 `stop`，该结果也不能还原旧请求的终止原因。见[批次复测记录](../tmp/api-label-failure-180/real-batch/report.json)。

现在先在模型响应边界识别明确拒绝，再解析标签：内容过滤或拒绝响应分别以 `output_refused`、任务错误 `INSIGHT_MODEL_REFUSED` 传递；服务失败／取消保留 `provider_failed`／`provider_cancelled`；意外工具调用保留具体格式错误类别。严格画像调用也检查这些状态及截断状态，合法 JSON 不能把异常结束变成成功。审计只保存白名单终止码、响应状态与截断原因，不保存拒绝正文；已完成标签保留，任务仍失败，不自动重试、跳过或换模型。[MiMo 接口文档](https://mimo.mi.com/docs/zh-CN/api/chat/openai-api)将内容过滤与正常结束分别定义，不能统称为标签格式错误。

分析调用使用独立严格策略：一次请求，不自动重试，不关闭上游格式要求后降级，不修复不完整 JSON，也不替缺失消息补标签。输出按严格 schema 校验，消息 ID 必须完整且唯一，出处必须存在并满足画像对象的身份约束。模型明确给出 null 和解释表示证据不足；网络或格式错误表示任务失败，两者不会混为一谈。

API 手动分析在一条完整标签通过结构、四字限制和出处校验后立即保存并更新进度，尚未闭合的 JSON 不作为结果。流正常结束后仍检查消息覆盖完整；缺项、重复、截断或后续错误会使任务失败，已保存的有效标签保留。画像依旧按窗口整理，不用未完成批次伪造画像。

失败、取消和应用退出保留已完成标签，界面标明任务未完成。「重新分析」创建新任务，默认复用符合条件的已保存标签，仅补充未完成部分；显式从头重算才重新识别全部消息。整理画像仍可能产生费用。重启不会自动恢复计费调用。清除账号同时取消其任务、清除画像和材料，迟到的模型结果不能重新写回。
