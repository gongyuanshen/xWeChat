# WeChatDataAnalysis 二次开发底座净化与验证计划书

## 一、目标与实施边界

**目标：** 基于现有公开源码和项目指定的原生运行时，移除高级版演示、商业推广及不可执行交互，保留真实业务能力，形成可启动、可验证、可维护的二次开发底座。

**工作目录：** `G:\WeChatDataAnalysis-main`  
**技术路线：** 延续 Nuxt/Vue、Electron、Python/FastAPI 和原生运行时架构，不开展整体重构或完整 EXE 反编译。

已确定的产品决策：

- 保留 WxCDN 媒体下载服务，移除套餐动画、升级推荐和加群入口。
- 将必要的连接状态、额度查询及已有兑换码操作移入“设置 → 聊天与媒体”。
- 保留解密、会话、聊天、联系人、朋友圈、收藏、本地语义检索，以及现有导出、年度总结等真实功能。
- 不实现消息修改、朋友圈发布、自动发送等缺少执行实现的高级功能。
- 本轮清理面向桌面应用及其构建依赖；独立官网不做整体改版，许可证和第三方声明保留。

**完成标准：** 清理后的功能范围明确，工程检查通过，真实数据回归有证据；未验证或已有故障单独列出，不以空数据、假响应或隐藏错误冒充成功。

## 三、接口与错误处理约束

- 不新增或修改公开后端 API、数据库结构及数据格式，不进行数据迁移。
- 媒体设置复用现有 `useApi`、`useCdnPlanStore` 和 `/api/cdn/plan`、`connect`、`redeem` 接口，不另建平行服务层。
- 保持聊天读取、解密、媒体解析、索引和原生进程之间的既有接口。
- `/api/cdn/plan` 的 HTTP 200 可能包含 `snapshot.error`，前端必须解析业务状态，不能按状态码直接显示成功。
- 已知业务错误在界面中明确展示；本次触及的未知异常保留上下文和错误日志，不通过空 `catch`、假数据或默认值掩盖。
- 不借本轮清理全面重写项目原有降级策略；发现与调试准则冲突的既有行为，记录并单独评估。
- `Integrity mode: development` 作为开发意图记录，不自行创造配置开关，不跳过原生摘要校验。
- “只读”指不修改微信源数据；应用自身的配置、缓存、模型索引和导出文件仍按原设计写入。

## 四、测试与验收

| 类别         | 必测场景                                   | 通过依据                                               |
| ------------ | ------------------------------------------ | ------------------------------------------------------ |
| 界面清理     | 侧边栏、设置、聊天右键、朋友圈入口         | 无高级演示、套餐推广、加群弹窗及仅展示不可用提示的操作 |
| 共用功能     | 复制文本、消息信息、引用定位、媒体操作     | 行为与原版有效功能一致                                 |
| 工程链路     | 开发启动、静态生成、桌面运行               | 无模块缺失、组件解析失败、未处理异常及非预期 API 错误  |
| 原生与解密   | 指定微信版本、密钥提取、数据库解密         | 读取实际数据库内容；不能仅凭服务就绪判定               |
| 聊天与联系人 | 会话切换、连续分页、边界消息、富文本       | 样本内容一致，分页无新增重复或遗漏                     |
| 媒体         | 本地存在、需要补下载、原始资源缺失         | 前两类按原能力工作；缺失时明确说明，不显示虚假成功     |
| 朋友圈与收藏 | 列表、详情、翻页、图片和已有刷新能力       | 与原版样本对照一致                                     |
| 媒体服务设置 | 无账号、账号切换、断网、额度不足、兑换失败 | 状态准确、不串账号、不自动消费兑换码、不吞错误         |
| 本地语义检索 | 模型加载、索引建立、语义查询、结果定位     | 确认真实向量检索路径被使用，不能以关键词回退结果通过   |
| 其他保留功能 | 导出、年度总结等受共享依赖影响的功能       | 相关自动化检查通过，并完成受影响路径冒烟验证           |

补充验收规则：

- 故意断网、输入无效兑换码等负向测试允许产生预期错误，要求错误可见且可定位；不以清空控制台为目标。
- 本地检索模型准备与云端 AI 回答分别记录；本轮检索验收不依赖云端生成回答。
- 自动化测试中的隔离样例不能替代真实账号、原生组件和外部服务集成验收。
- 兑换成功的实机验证需要用户指定可用于测试的兑换码；没有该条件时保留为待验收，不自动使用已有兑换码。
- 无真实数据或模型时，报告标注“工程检查通过、集成验收待完成”，不得宣称全部通过。
