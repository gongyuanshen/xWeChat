# 消息意图识别补齐

用户已授权补齐先前列出的功能，不改变手动画像及历史记录。

## 设计与边界

- 聊天页独立的“意图识别”开关，默认关闭，按账号、会话及完整模型来源保存。开启后分析当前已加载的文本和引用正文，纯标点也参与；翻历史和新消息追加到串行队列。关闭停止当前任务并隐藏自动标签，保存的结果下次恢复。
- 每次最多20条目标、3条相邻前文。前端仅提交身份、时间和原文SHA256；服务端从指定聊天数据源重新读取并校验。账号、发送者、同名成员、模型和原文变化严格隔离。
- API使用现有模型客户端流式输出，每个完整且有效的标签立即落盘并通过既有SSE送达；不完整、重复、超长、越界输出显式失败，保留已经验证的结果，不隐式重试。情绪和意图均限四字。
- Laya复用下载、CPU运行时与锁，增加上游细分类候选。规则只检索候选，最终分类由真实模型决定。粗分类继续用于统计画像。模型误判、低分未知和上下文溢出如实展示。
- 近期聊天与同一发送者已保存的画像提供弱参考，当前原文优先；画像不作为新证据。完整选取的摘要和交流特点保留，超预算明确失败。
- 单聊顶部显示最后一条已分析对方消息情绪。群聊顶部独立统计最近20条群消息；至少半数且唯一领先的已识别情绪才展示，无主导时显示不明确。翻历史不覆盖更新的情绪状态。
- 自动分析记录与手动画像历史分开存储。禁用、删除账号、退出和重启均有明确状态，不在失败或重启后自行重试。

## 实施和验证顺序

1. 后端入口契约、缓存/队列/取消/恢复、消息身份及画像来源校验，隔离测试。
2. 独立Laya细分类及真实人工样例；API增量JSON解析与两个现有协议的流式测试。
3. 手动画像复用新标签能力，保留统计与出处检查。
4. 前端开关、串行队列、断线读取、模型切换、标签与顶部状态；组件测试和浏览器人工夹具。
5. 人工样例的真实API与Laya端到端验收；前后端相关回归、构建、更新使用文档。按验证层次汇报，不宣称私聊实测或全量回归。

## 实施结果

上述功能已接入。相关后端258项、前端682项、桌面打包清单2项检查通过；最终窄屏布局修正后UI复验17项通过，生产生成34个路由。真实Chrome合成数据验收6项通过，记录见 `tmp/live-recognition-browser-approved-05/result.json`。

真实CPU Laya完成6批、17条人工消息的自动链路及缓存恢复验证；完整画像超出容量时明确失败。实际API仅尝试一次人工消息请求，当前服务 `127.0.0.1:12939` 拒绝连接（Windows 10061），因此真实API流式验收未完成。没有自动重试、切换服务或模型；ChatCompletions与Responses的SDK隔离测试通过不替代真实服务验收。详细记录和语义质量边界见 `docs/chat-insights.md`。
