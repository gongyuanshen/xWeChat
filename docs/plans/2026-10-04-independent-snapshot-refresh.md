# 独立快照持续刷新与读取切换

后续账号ZIP归档及完整删除已在下一步接通，见 [独立账号归档与完整删除](2026-10-04-independent-account-archive.md)。下文保留本阶段完成时的验收边界。

用户已授权沿现有路线继续开发。本轮复用已通过真实验证的源码密钥与整批验证快照，在当前账号上提供手动刷新和显式开启的定时检查。

## 设计合同

- 稳定账号目录及全局 output 不变，密钥、AI 数据、资源及用户资产保留原位置。源数据库通过集中路径解析函数读取已发布代次；无指针时仍读取原有目录，损坏指针必须报错。
- 所有库在独立 generation 中认证和完整性检查通过后，原子替换账号的 `_snapshot_current.json` 指针。每个 HTTP 请求和后台导出/索引任务固定代次，切换不更换已有任务的数据库路径。
- 来源相关派生缓存按代次隔离，不能因旧任务晚完成而把旧索引或统计当作新结果。禁止对已发布数据库执行缓存重建或实时同步写入。
- 手动单次、启动、停止及状态采用独立 API。仅使用来源路径严格匹配的已存密钥，拒绝自动获取密钥、Hook、旧组件或其他账号来源。
- 一次只运行一个账号的刷新任务。用户确认检查间隔30秒，显式启用；进程重启后默认关闭。源清单及内容未变不重建；任一采集、认证、发布、存储或权限错误停止，用户明确重试后恢复。
- 构建期间停止显示 `stopping`，构建结束不得再发布；进程停机等任务退出。保留所有 generation，不自动删除读取者可能持有的快照；默认2 GiB显式容量上限，达限报错停止。现有数据不参与自动清理。
- 前端显示检查间隔、运行/失败状态及最近成功时间，发布新代次后更新会话与当前消息；请求必须隔离账号与版本，不能以自动重试掩盖失败。

## 保证边界

生成快照仍是 `stable_observation`：复制窗口内完整源清单、状态和SHA-256相同，加密页面/WAL认证及SQLite完整性检查通过；这不等于微信源库的跨库事务快照。定时检查也不是消息即时通知。参考 [WeFlow 教程](https://doc.weflow.top/) 的读取思路及 [SQLite WAL 文档](https://www.sqlite.org/wal.html) 的读取与提交边界。
