# 自主密钥与快照构建：第二阶段首轮

沿用已确认的三阶段路线，复用现有内存扫描、数据库密钥验真与严格页面解密器。本轮推进自主取密钥到真实账号验收，并提供持续刷新所需的整批快照构建入口。

## 实现

- 独立模式的现有取密钥接口只调用源码扫描，绑定当前进程实际加载的 Weixin.dll，以账号的 session 和 message 数据库验证候选。禁止旧密钥缓存冒充扫描结果、禁止自动调用 wx_key Hook。
- 使用只读进程权限、正确的 Windows API 签名、确定的资源释放与超时/取消。权限不足、版本不匹配、候选未通过认证分别暴露错误，不启动或重启微信。
- 现有界面识别独立模式，不提供不可用的 Hook 切换。已验证密钥仍通过现有解密保存流程持久化，独立模式不生成旧组件专用缓存。
- 新快照在独立目录构建，核对整批源文件清单、状态和 SHA-256，完成全部数据库认证及完整性检查才生成新目录。任一失败保留原有账号数据，不重试、不发布部分结果。
- 新快照仅接收加密源库；明文复制不作为密钥认证成功，已有明文导入能力保留。界面在独立模式明确发送并仅接受 `pure_memory`，后端重启改变模式也不能把旧扫描标成独立验真。

## 保证边界

复制前后观测稳定且通过认证不等于持有 SQLite 事务快照。本轮新快照返回 `stable_observation` 保证级别，不自动替换正在读取的账号目录。连续调度、并发读期间的账号级切换及界面更新通知必须在后续实现并验证后才能启用；本轮不宣称已实现持续在线同步。

教程的 Windows 章节主要描述 Weixin.dll 字符串引用和特征定位，未给出完整可编译实现、密钥读取调用约定或兼容版本表。以本仓库源码及实际运行结果为准，不直接执行网页中的代码。

参考：[WeFlow 开发教程](https://doc.weflow.top/)、[SQLite 对运行中复制数据库的说明](https://sqlite.org/howtocorrupt.html#backup_or_restore_while_a_transaction_is_active)。
