# 独立离线数据链路：第一阶段

依据用户确认的三阶段路线，本阶段复用 Python 页面解密、WAL 合并、SQLite 聊天解析和目录导出。后续再开发自主取密钥、持续在线刷新及旧特殊导出格式替换。

## 实现边界

- 显式设置 `WECHAT_TOOL_DATA_MODE=offline`，不准备或加载旧 client/broker，不请求其授权服务；未设置时维持原有 native 模式。非法配置直接报错。
- 手动密钥经现有解密接口进入；源数据库与 WAL 必须稳定，所有完整性检查通过才原子发布单个数据库。错误不得填零、自动修复或产生成功输出。
- 离线模式下 `source=auto` 解析为 `decrypted`；明确请求 `realtime` 必须报错，不隐式切换来源。
- 第一阶段仅承诺 TXT、JSON、Excel 的目录导出。ZIP 签名、HTML 资源、WEC、自动取密钥与实时同步暂不支持；相关请求明确失败。
- 保留既有未提交变更，不改用户聊天库，不记录密钥，不把受控样本当作真实微信验收。

## 执行及验证

- [x] 严格解密：先重现非首页 HMAC 损坏、截断页/WAL、源变化及坏 SQLite 被接受的问题，再修正并运行解密/WAL 回归。
- [x] 独立启动：增加统一模式解析，接入 Python/Electron 启动和生命周期，验证 offline 完全不调用 native 初始化、后台实时准备或产品遥测。
- [x] 快照读取：复用账户来源策略和查询分支；验证自动来源、显式实时拒绝及数据读取错误。
- [x] 目录导出：复用现有任务管理与序列化，验证 TXT/JSON/Excel 的记录、发送者和时间一致，缺失/损坏分库报错。
- [x] 联合验证：独立临时目录中启动实际 API，使用受控加密 SQLite/WAL 输入完成解密、查询、导出；本机真实数据验证结果如下。

## 验收关注点

错误密钥、非首页篡改、WAL 尾部损坏、读期间源变化、输出覆盖失败均不可发布有疑点的单库结果。单库原子发布不等同于跨分库同时快照，真实验收需提供微信已退出后的完整 db_storage 副本；不会将在线复制稳定性检查宣称为跨库事务一致性。

## 自动验证记录

2026-10-04，最终联合回归 173 passed、1 skipped（Windows 符号链接权限）、24 subtests passed；桌面全部 127 passed。受控端到端使用真实加密 SQLite 样本与完整 API 生命周期，核对解密、消息及三种格式的实际文件，并设置 native、授权、产品遥测和外网调用失败探针。另以实际 `main.py` 子进程启动，通过 TCP 健康检查确认 `offline/decrypted`。

独立审查复现并关闭三项问题：导出缺失身份映射时误认本人、离线导出触发产品遥测、会话预览用旧缓存或吞掉坏分库异常。真实数据还促使 WAL 验证按 SQLite 代次边界识别回收尾，避免将合法旧代次尾误认为本代次截断。

全量 Python 回归未完成：`--maxfail=3` 在 `test_account_archive_cross_platform.py` 的三项 ZIP 签名测试因缺少原生 broker 停止。这属于尚未替换的 ZIP/WES 路径，没有用假签名使测试通过。前端没有本轮修改，未运行前端全套。

## 本机真实数据验收

用户正常退出微信后，以 `E:\xwechat_files` 下的真实账号库和本机已保存、来源匹配的密钥执行独立验收。输出及密钥副本仅在被 Git 排除的 `tmp/` 隔离目录中；没有修改原始微信目录。

- 真实 `POST /api/decrypt`：21/21 个业务数据库成功，页面认证及完整 SQLite 检查通过；3 个 `*_fts.db` 派生索引按原有扫描规则明确排除，未宣称全部24库解密成功。
- 会话接口读取160个会话。在一个普通私聊的3693条文本中选择最新100条，独立SQL对照 local_id、server_id、时间、发送者、收发方向及内容，6项差异数均为0。
- 相同100条分别经API导出JSON、TXT和Excel，逐文件回读匹配；核对最新记录、2名发送者及时间范围。
- 全过程前后源 `.db`/`-wal`/`-shm`/`-journal` 的文件状态与SHA-256一致；native client、broker、授权、lease及外网失败探针记录为空。
- 这是一个账号、一个私聊样本的离线验收，不代表所有微信版本、全部会话及所有消息类型均已验收；没有执行自主取密钥、在线持续刷新、媒体或特殊格式导出。
